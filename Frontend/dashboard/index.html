    Threat Prioritization Manual & Scoring Guide

    GroundedCVE Multi-Factor Scoring Architecture (Task 2.4)

    100-Point Mathematical Formula
    Score (0-100) = KEV (40) + AI Severity (40) + Public PoC (20) Max: 100.0 pts

    Standard CVSS scores often over-inflate theoretical internal flaws while under-rating actionable exploit primitives. GroundedCVE calculates priority from verified empirical threat intelligence.

    What Gets a HIGH / CRITICAL Score (70 - 100 Points)?

    🔥 CISA KEV Weaponization +40.0 pts

    Confirmed active exploitation in the wild cataloged in CISA's Known Exploited Vulnerabilities catalog. Threat actors are actively targeting exposed network endpoints.

    ⚡ Unauthenticated Network RCE +36 to +40 pts

    AI evaluated practical severity between 9.0 and 10.0/10. Attacker can execute arbitrary operating system commands, webshells, or payloads without providing any credentials.

    🔑 Perimeter Auth & Session Bypass +34 to +38 pts

    AI evaluated severity between 8.5 and 9.5/10. Flaws in SAML, OAuth, JWT, or admin routing gateways allowing remote unauthenticated actors to forge sessions and seize admin privileges.

    💻 Public Weaponized PoC +20.0 pts

    Verified exploit scripts or automated scanners published on GitHub or Exploit-DB. Drastically lowers the technical barrier to entry for opportunistic attackers.

    📡 Cloud SSRF / Metadata Exfiltration +32 to +36 pts

    Server-Side Request Forgery capable of querying cloud instance metadata (AWS IMDSv1/v2, GCP metadata) or internal microservices, resulting in IAM credential theft.

    📱 Mobile Exported Intent Hijacking +32 to +36 pts

    Exported Android Activities, Broadcast Receivers, or Content Providers that process untrusted intents without signature permissions, allowing malicious local apps to hijack app state or steal databases.

    What Gets a LOW / NEGLIGIBLE Score (0 - 39 Points)?

    🚫 Out-of-Scope Pre-Filter 0.0 pts

    Advisories affecting desktop operating systems, industrial IoT, hardware firmware, automotive CAN buses, or printer firmware. Automatically rejected by Task 1.2 classifier before scoring.

    🔌 Pure Denial of Service (DoS) +4 to +14 pts

    AI evaluated severity between 1.0 and 3.5/10. Flaws that only cause transient daemon restarts or memory leaks without arbitrary code execution, privilege escalation, or data exfiltration.

    🔒 High Credentials Required +8 to +16 pts

    Vulnerabilities requiring an attacker to already possess high-privilege credentials (e.g. cluster superadmin) or deep internal network access to exploit.

    📱 Local / Physical Access Required +6 to +16 pts

    Mobile flaws requiring physical USB debugging (ADB), unlocked device possession, or complex multi-step social engineering with direct user consent.

    ⚠️ CVSS Anomaly Discrepancy Gate (|Δ| ≥ 4.0) Quality Assurance Safeguard

    Whenever the discrepancy between vendor-assigned CVSS and Qwen 2.5's practical offensive rating exceeds 4.0 points, the advisory is flagged with a subtle discrepancy tag on the front page and a detailed troubleshooting note in the detail modal.

    CVSS Inflation Alert

    Vendor rates CVSS 9.8 based on worst-case theoretical math, but flaw exists on an internal unreachable component.

    CVSS Deflation Alert

    Vendor rates CVSS 5.3 as "moderate", but real-world chaining allows complete unauthenticated tenant compromise.

    Why Sequential Checking is Slow & How This Architecture Fixes It:
    1. Concurrent ThreadPoolExecutor

    Sequential checking waits for each network round-trip ($O(N \times \text{latency})$). With 30 parallel workers, 50 links are validated concurrently in 1.5 seconds instead of 35+ seconds.

    2. HTTP HEAD Lightweight Probing

    Rather than downloading full HTML bodies, images, and JavaScript via GET, the engine sends fast HEAD requests to verify HTTP 200 headers in 50–90 ms.

    3. Persistent Cache with 12h TTL

    Validated results are stored in link_health_cache.json. Subsequent lookups are instantaneous dictionary hits (0.001 ms), generating zero outbound network traffic.

    4. Async Ingestion Pipeline

    Link checking executes in the background when advisories are scraped or ingested, so user page loads and API requests are never blocked by external network lag.
